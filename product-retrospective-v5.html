5.0

万能营销工作台 · 约 66 天

时间线与工作路径

3/4 启动年度规划三大场景之一，优先推进服装营销。
3 月上旬先框定模特图、编辑、视频、文案和详情页等能力范围。
3 月中下旬让 AI 直接输出 PRD，手改与 AI 修改反复往返，文档变得冗长且空泛。
3 月底—4/13多次内审；原型和交互不清。4/13 完成评审，较 3/20 计划延迟约半个月。
4 月—5/9Trae 原型不完整；UI 设计师补全；架构师沟通被业务输入输出不清拖慢。
5/9 上线核心能力基本覆盖预设范围，之后持续修复卡顿、中断、裂图和上下文问题。

个人卡点与结果

用户调研滞后

没有先确认真实输入、满意输出和中间过程。

过早考虑架构

业务边界未清就讨论多 Agent、skill 和提示词。

PRD 先行

关注文档和工具，推迟内审，团队无法体验方案。

原型能力不足

AI 原型一般，最终依赖 UI 手工兜底。

验收标准后置

缺少用户可接受的输入输出标准。

上线质量偏弱

错误率偏高，30 天留存率持续递减。

复盘判断：约 60 分版本。重做时应聚焦电商营销闭环，强化整套物料和视频能力，谨慎使用自由对话 + 画布。

5.1

设计生产工作台 · 设计到生产闭环

时间线与工作路径

年初启动更新老旧服装设计能力，并在闭环终点衔接工艺单。
前期调研参考 SaaS 功能，沟通日本客户和国内运营，确定设计、图案、面料、矢量和工艺单范围。
4/28 首次内审功能范围较清楚，但原型完成度一般，PRD 开始多轮返工。
5/20 二次内审 + UI 内审继续用手工原型和 UI 讨论细节，工具与步骤不稳定。
5/26 技术方案对齐业务范围相对明确后与工程组对齐可行性。
6/1 需求评审其他能力反馈较好，用户整体满意并提出个性化需求。

个人卡点与结果

用户输入仍不够深

有客户和运营输入，但更多是一线转述。

四点没有前置

用户路径、边界、验收、技术方案形成较慢。

原型工具不稳定

AI 原型一般，最后大量手工绘制。

PRD 与原型返工

多轮对齐，UI 难以快速施工。

工艺单审核弱

用户没有意识到 AI 解析会强烈影响最终结果。

文字不可编辑

生图工艺单缺少文字分层和编辑能力。

复盘判断：效果整体较好，解决了旧能力和新场景问题。下一次先冻结四个前置点，用节点式交互和种子用户共创提高速度与验收质量。

5.2

灵感决策工作台 · 6/26—8/24

时间线与工作路径

6/26 产品讨论提出选品、企划、客户提案、款式裂变 4 个场景。
6—7 月 场景与数据取舍运营反复对逻辑；调研是否获取真实数据、供应商、格式和可行性。
7/7、7/21 讨论回顾筛选数据来源并验证质量，产品方案多轮重组。
约 1 周 种子用户共创补齐真实输入、过程、输出和验收标准，并制作 Demo。
8/10 对齐基于 UI 初稿，用 Codex/Coze 持续输出 HTML 可交互原型。
8/12 技术方案 · 8/17 UI 内审原型清晰后对齐技术，细化功能并推进 UI 终稿。
8/24 需求评审4 个预设场景收缩为 2 个上线场景。

个人卡点与结果

版本一开始过大

四场景并行，P0 筛选意识出现得太晚。

真实数据链路很长

从要不要做，到来源筛选、质量验证和应用。

验收后知后觉

场景确定后才发现输入、数据、过程、输出不清。

小版本打断主版本

无法衔接开发，中间插入多个小版本设计。

文档同步成本高

方案、重组版、主文档、PRD、原型、Agent 文档多次同步。

指标基线仍需前置

已列指标，但应在共创阶段开始采集。

复盘判断：后期比前两版顺畅，未再过早陷入复杂 Agent 架构。核心优化是第一阶段就做 P0 筛选、用户共创和数据可行性决策。

横向判断

问题从“业务没想清楚”逐步转为“范围、证据和基线如何治理”。

维度5.05.15.2结论
用户输入行为数据推理客户/运营转述种子用户共创 + 企业资料越来越真实
范围控制能力清单先行范围较早清晰4 场景后收缩 2 场景P0 仍需前置
原型对齐PRD 先行、UI 兜底手工原型返工HTML 原型先行可视化有效
验收标准后置模糊已有但不够快输入输出、确认门槛、证据和指标逐步可检查
主要风险稳定性、留存工艺单审核、编辑周期、文档治理技术风险转治理风险

新的推进方案

固定六步，并为每一步设置清晰的进入条件。

01 发现种子用户共创真实任务、输入、失败案例
02 定义用户路径与边界P0、非目标、最终产物
03 验收输入输出样例可接受、不可接受、异常
04 验证交互原型内审先体验行为，再讨论文字
05 实现技术与 Agent状态机、工具、提示词
06 复盘指标回收激活、完成、耗时、留存
硬门槛：没有真实输入输出样例，不进入大规模 PRD；没有可交互原型，不进入 UI 施工；没有验收标准，不冻结技术方案。

Codex 分工与优先动作

让 Codex 负责整理、生成、同步和验证，把产品经理时间留给判断与取舍。

Codex 直接承担

访谈结构化、路径初稿、样例库、HTML 原型、PRD/验收/Agent 同步、版本差异和复盘报告。

产品经理必须判断

问题价值、P0 场景、用户认可度、异常成本、范围冻结时机。

下一轮先做

只选一个高价值闭环；建立验收样例库；只保留一个产品决策基线。
